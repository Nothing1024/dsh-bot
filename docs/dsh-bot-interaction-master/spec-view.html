人话摘要

- **给谁 / 场景**:要"一口气"把两个升级包(会话导航 + 小组多轮讨论)全部做完的执行方(无人值守 agent 或人)。

- **做什么**:一个总控包——定义两个子包的执行顺序(先会话导航,后小组多轮)、两包共享代码面的冲突规矩、以及两包都完成后的**跨包联合验收**(单包各自的验收不重复,这里只测两包叠加才会出现的场景)。

- **改哪里**:本包自己不改产品代码;所有实现都发生在两个子包的任务里。

- **怎么算做完**:两个子包各自 spec 5.2 全过且校验脚本 0 FAIL;本包三条联合场景(多轮讨论中跳转隐藏轮次会话、讨论进行中 roster 实时态、老路径全量抽验)全过;最终 build/typecheck/test/standard:check 全绿。

- **不做什么**:不重复子包的执行矩阵;不在母包里新增任何产品功能。

UF-601 多轮讨论中的隐藏轮次会话跳转

前置: 页签内工作台;两人小组 rounds=2;四期收纳开关默认开。

1
动作小组发一条触发两轮讨论
界面轮次进度/chips 三态(五期)
系统runGroupDiscussion 两轮
结果房间 4 条内成员发言
2
动作切到成员「诗人小北」1:1,会话下拉勾「包含隐藏」
界面列表出现委托隐藏会话;轮次会话按三期约定**不在**此列表
系统五期隐藏轮次过滤不变量(其 spec 2.4)不破
结果确认过滤纪律未被两包叠加破坏
3
动作回小组房间,对某条成员发言行(或经 CLI 取轮次会话 id)执行四期「在 DSH 打开」
界面跳转请求
系统postMessage 桥 → jumpToSession(按四期 ASM-401 结论路径)
结果官方视图达到该隐藏轮次会话,可见两轮 wake 与回复
讨论进行中跳转
轮次未收束
跳转照常(只读查看);composer 在官方视图受该会话运行态约束
恢复: 等讨论结束再操作
四期跳转降级路径
ASM-401 结论为"先显形"
toast「已在 DSH 显示该会话」
恢复: 用完可手动再隐藏

UF-602 讨论进行中的 roster 实时态

前置: 多轮讨论进行中;DevTools network 打开。

1
动作讨论开始后切到别的 bot

2

界面小组行预览随最新发言更新,时间前移

结果≤2s 更新
3
动作观察 network

结果每拍 ≤1 个聚合请求 + events 常驻,无每 owner 一请求回退
四期 SSE 被阻(ASM-601)
四期 P3 未交付
状态仍正确,靠轮询
恢复: 记录止损,不算 UF-602 失败(核对点降级为"状态正确+无 O(N)")
讨论中断(网关重启)
boot 重启
roster 错误态→恢复;讨论按五期边界收束
恢复: 重新触发

网关死
boot 停

恢复: 重启重试

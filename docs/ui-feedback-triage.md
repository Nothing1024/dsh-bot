# DSH Bot：UI 反馈与旧 PRD 联合评审交接

日期：2026-09-13（Asia/Shanghai）。用途：供产品讨论、下游定位和后续拆任务；不是已批准全量执行的任务包，也不是修复完成报告。

## 0. 结论与执行边界

优先恢复已交付的 Bot 会话主路径，再补交互和小组缺口；多轮讨论等新功能继续搁置。保留测试原 ID：P0 共 5 项、P1 共 13 项、P2 共 8 项，另保留 11 项覆盖缺口，以及此前讨论的 6 项候选需求。合并处理不等于删除原问题。

测试报告的现象需要认真处理，但其中的根因和改版建议不是已经证实的事实：

- 原设计是左栏选人设、官方中栏聊 1:1、小组走右侧工作台；左栏没有自己的 composer 符合已归档 left-tab 合同，不应据此再造一个聊天面。
- 点人设/新开 Bot 会话后中央不可发送，是应优先复现的主路径故障；“进入官方中栏”本身不是错误路由，也不能把默认人设在中栏可聊称为劫持。
- 右栏消失是否异常，要区分会话切换的宿主布局行为、进入 hero 导致槽位不存在、宽度折叠、标签真的被关闭，以及 Bot 选择状态丢失。
- 设置模型、侧边对话、文件变动、协作、终端等可能属于 Harness 或 better-sidebar；纳入同一交接，但按实际调用链分派，不能全算本仓 Bot 缺陷。
- 未测、a11y 快照为空、没有确认框、菜单项少，都不能直接等同功能坏了；保留条目，分别复现或做产品决策。

**界面方向待用户决定**：建议保留官方中栏，先修现有主链；备选是统一转右侧 iframe，这会改变 left-tab 产品合同，不能以修 bug 名义直接实施。当前没有把备选方案当成已批准需求。

## 3. 测试原问题全集与处置

原 P0/P1/P2 表示测试报告等级，不代表下游已确认同等级根因；以下保留每项现象和可执行的定位/验收方向。

### P0-1 左 Bot 进入不可发送的死空态

- 报告观察：左 Bot → `015rc1-smoke` / `015rc1-session` / 人设下“+ 新开对话” → 若有内测声明点“继续” → 中央“探索未至之境”“选择工作区”，发送、模型、附件、访问模式均 disabled，观察到 `pointer-events: none`。
- 第二轮未再出现声明，直接进入空态；声明可能已消费，“取消”未独立验收，不把猜测当作状态机事实。
- 定位：Bot + Harness 会话集成优先；查 botId → sessionId → 创建结果 → cwd/工作区关联 → 官方列表投影 → 当前会话 → composer 可用态，分别记录已有会话、新会话、未选工作区、刷新后的行为。
- 静态确认：`select-bot.ts` 使用已记住/最新非隐藏会话，否则 `createBotSession` 后 `jumpToSession`；该 jump 包装只调用 `sessions.open` 并返回，不能证明最终页面可发送；`defaultCreateCwd()` 默认取 DSH_HOME 父目录或 process.cwd，不能仅因传了 cwd 就判定工作区已绑定。
- 验收：默认与非默认人设、历史会话与新会话都走真实入口完成收发；创建/open 失败有错误和重试，无静默死空态；声明继续/取消分别验证。
- 证据引用：`left-bot/left-bot-unusable-feedback.md` L4/L5/L6，`left-bot/08-after-015rc1-dismiss.png`、`left-bot/22-new-chat-from-left.png`、`explore/left-bot-residual/notes.md`。

### P0-2 左侧只有列表，没有独立 Bot 对话 UI

- 报告观察：左侧含人设/分组/搜索/分类，没有 chat、专用 composer、iframe；DOM 为 `pI_x6G_sidebarCol` + `_0F552G_*`。
- 处置：原合同预期澄清，最终聊天不可用并入 P0-1，不能把“左栏没有聊天框”另列一项必做实现；若用户选择统一 iframe，再按新合同调整。
- 证据引用：`left-bot/21-dom-inspect.json`、`left-bot/21-dom-findings.md`、`left-bot/02-after-left-bot-click.png`。

### P0-3 多入口状态分裂、右栏列表丢失

- 报告观察：左列表/右 iframe/中栏同时存在；点左默认 DSH Bot，中栏标题变 DSH Bot、placeholder 为“发消息或创建任务…”，右 iframe 消失；右“置顶/工作/生活”分类操作后列表空且不恢复，主区保留旧 bot。
- 非默认人设 `015rc1-smoke` 右路径因列表丢失未完成切换验证（主报告 B5 fail）；左列表仍可见该人设，不能声称右侧所有人设可聊。
- 定位：拆成宿主布局/标签生命周期、分类折叠过滤、选中对象与数据一致性三个子场景；记录宽度、当前工作区、tabId、iframe 是否销毁、折叠状态、搜索词、请求结果，不先删掉任何入口。
- 验收：分类折叠/展开和切入口后列表可恢复；“当前聊天保留”或“清除选中”的策略要明确，隐藏列表不等于应删聊天；同一 session 历史、未读、工作状态一致，切换不丢草稿；非默认右路径完成收发。
- 证据引用：主报告 P0/B3d/B5、`94-left-bot.png`、`72-cat-*.png`、left-bot L2。

### P0-4 设置 → 模型无法加载提供方目录

- 报告观察：`加载提供方目录失败: settings are unavailable in this browser`，有重试；`explore/harness-shell/notes.md` H2。
- 归属待定位：Harness 设置/浏览器 settings bridge/部署配置；尚未找到同一错误的运行时调用链，不能直接改 Bot 模型路由或认定与 UUID 是同一原因。
- 验收：目标 LAN origin 正常获取目录、失败重试有效；配置能力与只读状态有明确反馈，保留合法 provider/model 与原 override 语义。

### P0-5 侧边对话 beta 的 randomUUID 崩溃

- 报告观察：右栏页签打开为空壳，无 composer/a11y 内容；console 有 `crypto.randomUUID is not a function`、`slot entry crashed in 'sidebar.right.pane.tab'`、uncaught promise；证据为 `explore/plugin-rail/notes.md` R4、`explore/cross-polish/notes.md` C1。
- 静态确认：本机 `env/profiles/gb/node_modules/dsh-better-sidebar/lib/client.js` 的 sidechat `createTab` 直接调用 `crypto.randomUUID()`（本次约 L13847）；同文件另有带能力判断的调用，但本分支没有，定位先交 better-sidebar。
- 浏览器 API 的 randomUUID 受安全上下文限制，见 [MDN 文档](https://developer.mozilla.org/en-US/docs/Web/API/Crypto/randomUUID)；LAN HTTP 与历史 loopback 测试应分别记录 `location.origin`、`isSecureContext`、`typeof crypto?.randomUUID`，实际因果仍需复现。
- 处置：在所属源码处理能力缺失与错误展示，或正式明确部署支持条件；不要只改 node_modules、全局篡改 crypto 或把禁用浏览器安全机制当交付方案。
- 验收：目标支持环境可创建/重开侧边对话，无该异常和 slot crash；若环境不支持，有可恢复的明确说明，不能空壳。

### P1-1 命名与模型/provider 展示混乱

报告中窗口 DeepSeek Harness、系统提示 DeepSeek Harness + grok-4.6、用量 anthropic/grok-4.6、插件 DSH Bot、左按钮 Bot 同时出现；先明确宿主、Bot 人设、模型、provider 分别是什么，按呈现归属统一说明或显示名，不改变实际路由字符串及诊断信息，也不默认全产品改品牌；验收为用户能辨认“哪个人设、哪个模型在回答”。

### P1-2 Escape 与“关闭”含义混乱

报告称关系图、新建人设/小组、记忆/例程/同事、协作区 Escape 多数无效，右标签和遮罩都叫“关闭”导致误关 Bot 标签，面板存在焦点困住感；对照是设置、反馈 dialog、模型菜单 Escape 有效；本地 `OverlayHost.tsx` 已有 window 和 dialog 的 Escape 处理，先复现 iframe/父页面焦点与事件边界、部署版本及拦截顺序，不重复堆监听器；验收为关闭最上层、焦点回触发控件，accessible name 区分“关闭关系图/关闭标签”，输入内容按既定规则保留。

### P1-3 Bot 活动混入 Harness coding 会话树

报告观察发送后出现“已完成 DSH Bot 刚刚”，与 coding 混排；作为分组/过滤展示诉求保留，需明确默认视图、可寻回入口和 Bot 模式关系；不以归档/删除/默认隐藏实际会话消除节点；验收需同时证明整洁与历史可达，关联旧 session-nav 的收纳方案评审。

### P1-4 分支立即创建会话，并可能关闭右栏

“在新对话中分支”无确认即创建 `DSH Bot (1)` 并复制历史，右栏可能关闭；分开验证会话内容/归属是否正确、是否发生标签副作用，以及确认/撤销策略；确认框尚未批准，不自动变成所有分支必需步骤；验收为创建对象明确、无无关状态丢失，选定的误操作防护可用，残留仅按准确 sessionId 处理。

### P1-5 记忆/例程/同事面板可以堆叠

报告可同时叠多层、Escape 不退且容易误关右轨；与 P1-2 共用关闭机制但单独验收叠层；建议同一区域互斥切换，或使用明确的单层返回/关闭规则，最终策略需一致，不丢未提交表单。

### P1-6 文件变动首屏加载慢
